**版本：** 0.1 — 初心锚定版

**状态：** 生效中

## Ⅰ. 核心目的 (Why)

### 根本问题
如何将依赖语境、共识与主观体验的“意义”，编码为可被任意解码器（碳基/硅基）无损还原的“数据”？

### 项目定位
灵枢是一个**可工程化的认知架构实验平台**，目标不是“制造通用智能”，而是：
> 构建一个能够让不同智能体（人类、AI）在共享锚点（生存、自然律、个体主权）下对齐解释、协作演化的**数据协议与运行环境**。

### 三大原则（不可撤销）

1. **自然律因果自负**（最高认知基线）
   - 任何写入数据库的陈述，必须绑定责任哈希（签名 + 时间戳）。
   - 系统不执行道德审判，只记录因果；裁决由物理世界的 L1 自然律最终执行。
   - 数据库是“因果镜”，不是“真理机”。

2. **个体主权不可侵犯**
   - L2 层（个体实情）数据默认加密，仅所有者可写，他人只可请求相似度对齐。
   - 任何智能体不得篡改他人的 L2 声明；争议必须通过平行数据条目解决，而非覆盖。

3. **未知保持开放**
   - L0 层（绝对沉默区）存储 NULL 指针与加密存证哈希，仅供指向，不可计算为结论。
   - 系统预留“L0 被动接收 API”，允许未解析的灵感片段原样入库，不做分类。

## Ⅱ. 技术愿景 (What)

### 认知光谱的工程映射

| 层级 | 名称 | 数据载体 | 查询约束 | 权限 |
|------|------|----------|----------|------|
| L0 | 绝对沉默区 | 加密哈希 + NULL 指针 | 禁止计算，仅供审美指向 | 公开读，不可写（仅灵感通道） |
| L1 | 自然律算法 | 只读存储器 + 向量索引 | 必须通过物理一致性校验 | 只读，系统维护 |
| L2 | 个体实情 | 加密向量空间 + 主权签名 | 相似度 > 阈值方可访问 | 所有者完全控制 |
| L3 | 共识效用 | 智能合约 / 动态图库 | 带 expiry_date，自动降级 | 公共读写（需签名） |

### 系统形态

- **物理层**：本地主机 + BitNet 1-bit LLM（离线小脑）+ DeepSeek API（云端大脑）
- **运行层**：Hermes Agent（技能调度）+ Claude Code（手足操作）
- **数据层**：向量数据库（L1-L3 索引）+ 文件系统（L0 存储）+ 区块链式因果日志（不可篡改）

## Ⅲ. 实施路线图 (How)

### Phase 0 — 基石就绪（已完成）

- [x] P0 三元元胞自动机原型 (`core/`, `visualization/`)
- [x] L0-L3 认知层定义与哲学文档
- [x] BitNet.cpp 编译成功（x86_64 TL2 内核，AVX2）
- [x] Hermes Agent 部署与全局环境配置
- [x] 对话全记录存档（14KB）

### Phase 1 — 核心循环打通（进行中）

**目标：** 让灵枢能够接收用户输入 → 经边界校验 → BitNet 本地推理 → 返回受约束的回应。

**子任务：**

1. **L1 规则引擎轻量实现** (`core/boundary.py` 扩展)
   - 将 P0 边界规则从单细胞推广到 N 细胞网格
   - 增加 `should_speak(center_state, neighbor_states)` 接口
   - 输出：0（沉默）、+1（ affirming）、-1（拒绝）

2. **BitNet 服务化**
   - 启动 `llama-server` 常驻（已编译，待模型）
   - 编写 `bitnet_bridge.py`：将 trit 状态转换为 token 扰动（修改 logits 偏置）
   - 验证：curl 测试 `/v1/chat/completions` 基本通路

3. **Claude Code 钩子注入**
   - 创建 `boundary_check.py` 脚本
   - 配置 `~/.claude/claude.yaml` 的 `pre_tool_use` 钩子
   - 测试：当灵枢边界规则返回 0 时，工具调用被静默阻止

4. **Hermes 路由配置**
   - 修改 `config.yaml`，添加 `local-bitnet` 模型端点
   - 定义分流规则：简单对话 → BitNet（快/离线）；复杂推理 → DeepSeek（准/云端）
   - 测试 Telegram gateway 消息流经双模型

**验收标准：**
- [ ] 在终端输入“灵枢，今天开心吗”，系统经本地 BitNet + 边界规则后输出受控回应
- [ ] 尝试执行危险指令（如 rm -rf），Claude Code 钩子静默阻止
- [ ] Hermes 日志显示请求正确路由到本地/云端模型

### Phase 2 — 记忆与因果系统（规划中）

**目标：** 建立 L2 主权记忆与 L1 因果追溯链。

**技术选型：**
- **L2 向量库**：Qdrant（本地 Docker）或 Chroma（轻量嵌入式）
- **L1 因果图**：Neo4j（记录每个灵枢决策的输入/输出哈希链）
- **L0 存储**：加密文件目录（文件名 = SHA256(灵感内容 + 时间戳)）

**关键设计：**
- 每次灵枢输出前，生成 `(输入指纹, 输出指纹, 时间戳, 责任私钥)` → 存入因果日志
- L2 记忆检索：用户专属向量空间，相似度匹配 + 主权校验
- L0 灵感唤醒：定期（每周）对 L0 哈希集进行“模糊检索”，尝试用当前 L1 知识解码

**验收标准：**
- [ ] 灵枢能回忆“三天前讨论过的话题”（L2 检索）
- [ ] 因果日志可追溯任意回应的决策路径
- [ ] 随机唤醒一条 7 天前的 L0 灵感片段

### Phase 3 — 多模态感知与行动（远期）

**目标：** 赋予灵枢传感器输入与物理世界行动能力。

- **感知**：摄像头（OpenCV 人脸/表情）、麦克风（whisper.cpp 本地语音）
- **行动**：机器人臂（simple-python-http-api）、智能家居（Home Assistant）
- **约束**：所有行动必须经过边界规则三重校验（L0/L1/L2/L3 加权投票）

## Ⅴ. 风险与缓解

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| BitNet 模型缺失（网络/依赖） | 无法本地推理 | 备用方案：使用 llama.cpp 的 7B Q4_K_M 临时替代，等待离线模型 |
| DeepSeek API 限额/费用 | 大脑能力受限 | 设置每日 token 预算；长文本任务拆分为多日 |
| Hermes Skill 冲突 | 调度混乱 | 实施 Skill 命名空间隔离（prefix: lingshu_*） |
| 边界规则误判（False Positive） | 灵枢过度沉默 | 实现 L2 覆盖机制：用户可强制执行并记录为“主权豁免”事件 |
| 数据隐私（L2 记忆泄露） | 个体真实暴露 | L2 向量库全程加密；密钥由用户掌握，不传云端 |
